## 1. 피드백 항목

### 1-1. AI 튜터 작동 불가
- "공도쌤에게 물어보기"에서 어떤 질문을 보내도 `"답하지 못했어요. 다시 물어봐요!"` 만 응답
- claude api 확인 필요

### 1-2. 생성형 AI 캐릭터 → 넷마블 IP 캐릭터 교체

| 위치 | 화면 | 교체 대상 |
|---|---|---|
| 1 | 드로어 헤더 "공도쌤에게 물어보기" 옆 아바타 | **슬기** |
| 2 | 우측 하단 플로팅 FAB 버튼 (AI튜터) | **슬기** |
| 3 | "AI가 게임을 만들고 있어요" 모달의 큰 캐릭터 | **데니스** |
| 4 | 채팅 말풍선의 봇 아바타 | **데니스** |

### 1-3. 게임생성환경
- 뒷 배경 / 보드판 디자인 필요
  - 유나님이 사무실에서 보여줬던 "클로드 디자인 예시 배경" 처럼 예시 배경이 들어가야 함
- 1~2차시는 40칸이 아닌 **12칸** 시작
- 3차시는 IP(데니스·슬기)가 이미 적용된 상태로 시작

### 1-4. 바이브코딩 문서
- **1차시**: 40칸→12칸 수정 후 생성했는데도 그대로 40칸 생성됨 (버그)
- **첫 생성부터 12칸 기준**으로 범위 축소
- **1~2차시 상세 설명**: 칸마다 국가·수도·건축물에 대한 1~2줄 설명 추가
- **2차시**: 6개는 미리 채워두고, 6개는 빈칸 (학생이 AI튜터/검색으로 입력 → 보드판 반영)
- **3차시**: "우주맵 / 하늘색 / 데니스 능력 더 강하게" 예시 모두 삭제, "캐릭터별 특수 능력 적용" 텍스트도 삭제

### 1-5. 기타
- 첫 화면 진입시 **배경음 삭제**

## 3. 잘 안 되거나 미반영인 점

### ⚠️ 3-1. AI 튜터 — 근본 원인 미확정 (블로커)
- KV rate-limit DNS 실패가 `/api/chat`을 500으로 죽이던 경로는 막았지만, 피드백 스크린샷의 "답하지 못했어요…"는 그 경로 외 다른 원인일 수 있음
  - Vercel 환경의 `ANTHROPIC_API_KEY` 누락/만료
  - 모델명 변경
  - 502 upstream 등
- `.env.local` 엔 키가 있지만, 실제 배포 (`gongdo-ai-game-113087078206.asia-northeast3.run.app`) 에서 검증한 흔적이 없음
- **다음 액션**: 배포 환경의 `/api/chat` 응답을 직접 콜해 `error` 코드를 확인 → 이번에 추가한 `console.warn` 로그를 운영 콘솔에서 읽기

### ⚠️ 3-2. "1차시 1~2줄 설명 추가" 의도와 다르게 처리
- **피드백**: 각 칸마다 국가·수도·건축물 1~2줄 설명 추가
- **현재**: 1차시는 칸 목록 자체를 제거함 ([lesson1.md 변경 사항](../앱_app/차시_lessons/lesson1.md#L55-L70))
- 1차시는 "보드 뼈대" 차시라 의도적인 단순화일 수도 있는데, 피드백은 1·2차시 모두 칸별 설명을 원하는 톤
- **결정 필요**: 1차시에 도시·설명을 넣을 건지

### ⚠️ 3-3. "6칸 빈칸 학생 입력 → 보드판 반영" 인터랙션
- 2차시 md엔 `__________` 빈 줄이 있지만, 학생이 텍스트로 채워 넣었을 때 `parseCities` 가 정상적으로 무시/대기하는지 검증 안 됨
- 학생이 `7칸 : 영국 런던: 빅벤 / 6200골드` 형태로 입력 후 [▶ 시작] 누르면 그 입력이 보드 cell 데이터로 들어가는지 회귀 테스트 필요

### ⚠️ 3-4. "보드판 40칸 그대로 생성" 버그
- cellCount default 를 12 로 바꿨지만, 학생이 md 를 수정하지 않은 채 시작하거나 다른 차시에서 넘어왔을 때 캐시된 board 가 40칸으로 남는 케이스가 있는지 확인 필요
- 2차시 `lesson2.md` 엔 `12칸 보드판` 이 명시되어 있어 정상 흐름으로는 12칸으로 가야 함
  - → 1차시에서 `## 보드판` 본문 한 줄만 있고 다른 차시 md 를 학생이 열었을 때 분기 검증 필요

### ❌ 3-5. "유나님이 보여준 클로드 디자인 예시 배경"
- 이번에 `lesson-background.js` 프롬프트를 "보드 뒷배경 전용" 으로 다듬고 `has-bg-image` CSS 오버레이를 추가했지만, **유나님이 사무실에서 시연한 그 배경이 무엇이었는지 컨텍스트가 없음**
- 어떤 형태의 예시였는지 확인 필요
  - 샘플 이미지인지
  - 고정 프리셋인지
  - 특정 프롬프트 톤인지
- 현재 코드는 "학생이 묘사하면 즉석 AI 생성" 인데, 피드백은 "예시 배경이 미리 들어가 있어야" 하는 톤일 가능성

### ⚠️ 3-6. 3차시 캐릭터 특수 능력 텍스트 (배포 확인 필요)
- 현재 [lesson3.md](../앱_app/차시_lessons/lesson3.md) 엔 해당 라인이 이미 없음 → 코드상 반영됐다고 볼 수 있음
- 단, 피드백 스크린샷에 노란 하이라이트로 표시된 부분이 **운영 배포 lesson3.md 의 구버전일 가능성** → 최신 배포 확인 필요

## 4. 작업상 어려운 점 (수기 확인 필요)

이번 사이클에서 피드백을 코드에 옮기는 과정 자체가 매끄럽지 않았음. 기존 구조와 새 요구가 부딪히는 지점이 여러 군데여서, 자동으로 검증하기 어렵고 **사람이 한 번씩 눈으로 확인해야 안전한 부분**이 남아 있음.

### 4-1. "12칸 vs 40칸" 의 이중 진실 공급원
- 1·2·3차시 md 엔 `12칸 보드판` 이 명시되어 있고, 파서 default 도 `12` 로 바꿨음
- 하지만 [bluemarble/index.html](../앱_app/에셋_assets/샘플게임_samples/bluemarble/index.html) 내부의 `BASE_CELLS` / 도시 보드 fallback 등에는 여전히 40칸 기준으로 설계된 분기가 남아 있어, 학생이 md를 일부만 수정한 상태에서 [▶ 시작] 을 눌렀을 때 어느 쪽이 우선되는지 케이스별로 다름
- → **수기 확인**: 1·2·3차시 각각 "수정 안 함 / 보드판 줄 변경 / 칸 목록만 변경" 3가지 시나리오 직접 클릭 테스트 필요

### 4-2. "보드 색상" 섹션이 색·이미지 두 가지 의미를 겸함
- 같은 `## 보드 색상` 한 섹션이 (a) 단순 색상 fallback, (b) AI 이미지 생성 프롬프트, 두 경로로 동시에 흘러감 ([app.js parseLessonBackgroundPrompt](../앱_app/공용_public/js_스크립트/app.js#L670-L710))
- "기본 보드" / 단순 색상명 / 풍부한 묘사 — 세 케이스를 분기로 처리하지만, 학생이 어중간한 길이 ("따뜻한 노란색") 로 쓰면 어느 쪽으로 갈지 코드만 봐선 단언이 어려움
- → **수기 확인**: "기본 보드" / "하늘색" / "노을 하늘처럼" 세 입력 후 실제 화면 비교

### 4-3. lesson md ↔ 운영 배포 사이 시차
- 워킹 트리의 lesson 1·2·3 md 가 모두 수정되어 있지만 아직 커밋되지 않음 (`git status` 상 modified)
- 피드백 스크린샷이 가리키는 화면은 **운영 배포** 기준이라, "이미 반영된 줄 알았던" 항목 (예: 3차시 캐릭터 특수 능력 텍스트) 이 사실 배포에 안 올라가 있을 수 있음
- → **수기 확인**: 현재 워킹 트리를 커밋·배포한 후 운영 URL 에서 lesson 본문 재검수

### 4-4. 캐릭터 위치 4종 일관성
- 슬기·데니스 PNG 4곳 교체는 코드 검색으로는 다 잡혔지만, 실제 화면에선 모달이 열리는 순간 / 채팅 첫 봇 응답 / FAB hover 등 **타이밍에 따라 fallback 이모지(👧/👦)가 잠깐 보이는** 회귀가 종종 생김
- onerror fallback 이 의도대로 "이모지 → 그대로 유지" 인지, "이모지 → 잠깐 보였다가 PNG 로 교체" 인지 보장이 약함
- → **수기 확인**: 느린 네트워크 (DevTools → Slow 3G) 로 4 위치 모두 클릭해 fallback 깜빡임 확인

### 4-5. 2차시 빈칸 입력 인터랙션 미검증
- 3-3 항목과 같은 맥락 — 학생이 `7칸 : __________ / ____골드` 줄을 직접 채워 넣었을 때 `parseCities` 가 어떻게 동작하는지 단위 테스트가 없어 손으로 채워보고 [▶ 시작] 눌러야 함
